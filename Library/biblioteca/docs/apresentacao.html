Projeto Capstone · demonstração final

Biblioteca.

Encontre sua próxima leitura. Organize sua estante. Acompanhe seus empréstimos em um só lugar.

Fala: “Olá! Este é o Biblioteca, um catálogo digital que transforma a descoberta de livros em uma experiência pessoal de leitura.” Apresente o problema em uma frase e passe para a visão geral.

01 · O desafio

Descobrir é fácil. Organizar tudo é outra história.

  • DescobertaBuscar livros por título, autor e categoria.
  • DisponibilidadeSaber se há exemplares para emprestar ou reservar.
  • ContinuidadeManter leituras, desejos e histórico organizados.
  • Uma solução integradaConectar catálogo público a uma biblioteca pessoal persistente.

Fala: “O desafio não era só encontrar um livro: era conectar a busca a uma rotina de leitura e circulação.” Explique que a disponibilidade é simulada, pois a Open Library não fornece estoque físico.

02 · O produto

Da busca à estante pessoal.

Descobrir→ Explorar detalhes→ Emprestar ou reservar→ Organizar leituras
  • CatálogoPesquisa, filtros, ordenação e detalhes com capas.
  • ContaCadastro, login e sessão segura com JWT.
  • CirculaçãoEmpréstimo, devolução, disponibilidade e reservas.
  • EstanteListas “Lista de desejos”, “Lendo” e “Concluído”.

Fala: “O catálogo é público; para emprestar e criar uma estante, a pessoa entra ou cria uma conta.” Mostre o fluxo completo na demonstração em vez de ler a lista.

03 · Como foi construído

Uma interface. Uma API. Dados que permanecem.

  • FrontendReact + TypeScript + Vite + React Router.
  • BackendExpress + validação Zod + proteção Helmet e rate limit.
  • DadosSQLite persistente para usuários, empréstimos, reservas e estante.
  • Catálogo externoMetadados e capas consultados na Open Library.
Navegador→ API Express→ SQLite Navegador→ Open Library

Fala: “A interface não grava empréstimos no navegador: ela chama a API, que valida regras e persiste os dados em SQLite. Senhas recebem hash e a sessão usa token assinado.”

04 · Ensaio da demonstração

Uma demonstração em 90 segundos.

  1. 1. ExploreBusque “Machado de Assis” e aplique um filtro.
  2. 2. DescubraAbra um livro e destaque detalhes e disponibilidade.
  3. 3. EntreUse uma conta de demonstração preparada ou cadastre uma.
  4. 4. ConcluaEmpreste, marque “Lendo” e confirme na estante e nos empréstimos.

Fala/ação: Use uma conta e um livro que já foram ensaiados. Deixe uma segunda conta pronta para repetir o fluxo; não mostre dados pessoais. Se a rede falhar, mostre a estante já persistida e explique a separação entre API e catálogo externo.

05 · Qualidade e próximos passos

Pronto para demonstrar. Transparente sobre o que falta.

  • Qualidade verificadaBuild, lint e teste de integração da API.
  • ExperiênciaLayout responsivo, teclado, foco visível e tema escuro do sistema.
  • Limite atualEstoque ilustrativo; catálogo depende da disponibilidade da Open Library.
  • Próximo marcoPublicar frontend e API com banco persistente e links configurados.

Fala: “O ensaio também é honesto sobre limitações. O inventário é simulado; em produção, a API precisa de armazenamento persistente, origem CORS e segredo configurados.” Não anuncie um link ao vivo até o deploy estar validado.
